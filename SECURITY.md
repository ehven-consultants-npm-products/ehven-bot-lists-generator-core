# Security

Report suspected vulnerabilities privately to [security@ehven.com](mailto:security@ehven.com).
Gilad Ehven monitors this address and coordinates triage and corrective releases.
Include the affected version, a minimal reproduction, impact and relevant environment.
Send synthetic examples; omit credentials and private site content. Do not post a
suspected vulnerability in a public issue before coordination.

Security fixes target the latest stable 1.x release. Upgrade to the latest patch.
No response-time or commercial support service level is promised.

The package validates explicit public inventories and generates text. It does not
authenticate users, discover private content, enforce crawler cooperation or host
routes. Callers own publication approval, authorization, HTTP policy and generated
file placement. A future publication date does not keep an approved page private.

Confirmed defects are addressed with a new version and a public security notice
when disclosure is appropriate. Consumers should review the notice, upgrade and
regenerate affected output. Never assume a compromised older version is a safe
rollback target. If a report exposes credentials, revoke and rotate those credentials
in the affected service as part of incident handling.
